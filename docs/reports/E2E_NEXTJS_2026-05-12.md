### Auth Mechanism (Confirmed from bundle analysis)
- **Server-side guard:** Next.js middleware checks `Cookie: token=<JWT>` — issues 307 redirect to `/login?redirect=<path>` if absent
- **Client-side auth:** `localStorage.getItem("token")` — set on login, cleared on logout
- **Auth store:** localStorage keys `token`, `refreshToken`, `user`, `ocs_profile`
- **Logout clears:** `token`, `refreshToken`, `user`, `ocs_profile` (does NOT clear legacy keys `ainative_access_token`, `opencap_token`)

## Bug Report

### BUG-001 — No redirect after successful registration
- **Severity:** Medium
- **URL:** `https://opencapstack.com/register`
- **Reproduction:**
  1. Go to `/register`
  2. Fill in all fields and submit
  3. API returns 201
  4. Page shows "Check your email" message
  5. User must manually click "Go to sign in"
- **Expected:** Auto-redirect to `/login` (or `/login?message=check-email`) after 2-3s
- **Actual:** User stays on `/register` with static success message

### BUG-002 — New account login blocked by unverified email with unclear UX
- **Severity:** High
- **URL:** `https://opencapstack.com/login`
- **Reproduction:**
  1. Register a new account at `/register`
  2. Without verifying email, go to `/login`
  3. Submit valid credentials
  4. API returns 401 "Invalid credentials" (backend rejects unverified accounts)
- **Expected:** Login page shows "Please verify your email before logging in" banner, with a "Resend verification email" button
- **Actual:** Generic 401 error or "Login failed. Please check your credentials." — user does not know why login is failing
- **Note:** The `/login?error=verify-email` URL param DOES render the correct banner, but this is only shown when the redirect from the backend includes that parameter. In the direct login flow, the error message is generic.

### BUG-003 — Rate limit 429 shows misleading "Check your credentials" error
- **Severity:** Medium
- **URL:** `https://opencapstack.com/login`
- **Reproduction:**
  1. Attempt login 3-4 times within a short window
  2. API returns 429 with `retryAfter: 2836`
  3. UI shows "Login failed. Please check your credentials."
- **Expected:** "Too many login attempts. Please wait X minutes before trying again."
- **Actual:** Same error message as invalid credentials — user thinks their password is wrong and may lock themselves out further

### BUG-004 — Registration 500 Internal Server Error on repeated test emails
- **Severity:** Medium
- **URL:** `https://opencapstack.com/register`
- **Reproduction:**
  1. Register with any email that already exists in the system
  2. API returns 500 "Internal server error"
- **Expected:** 409 Conflict with message "An account with this email already exists"
- **Actual:** 500 with no helpful message — indicates the backend is not handling duplicate email registration as a controlled error

### BUG-005 — Logout does not clear legacy localStorage auth keys
- **Severity:** Low
- **URL:** `https://opencapstack.com` (all pages)
- **Details:** The logout handler in `9601-*.js` chunk clears `token`, `refreshToken`, `user`, `ocs_profile` but does NOT clear `ainative_access_token` or `opencap_token`. If any component reads from these legacy keys, it could maintain a stale auth state post-logout.
- **Affected keys:** `ainative_access_token`, `opencap_token`

### BUG-006 — AINative JWT not accepted by opencap backend (token format mismatch)
- **Severity:** High
- **URL:** `https://opencapstack.com/api/v1/stakeholders` (and all API endpoints)
- **Details:** An AINative JWT (from `api.ainative.studio`) passed as `Authorization: Bearer <token>` to the OpenCap backend returns a 400 error: `{"error":"companyId is required (query param or user profile)"}`. The backend does not reject the token as invalid (no 401) but also does not map the AINative user to a company. This means **authenticated users who log in via AINative OAuth have no company context and cannot access any data**.
- **Reproduction:**
  1. Login via AINative (`api.ainative.studio/v1/auth/login`)
  2. Use returned `access_token` to call `/api/v1/stakeholders`
  3. Returns 400 — not 401 (token is valid) but no company association
- **Impact:** Any user who registers/logs in via AINative OAuth (including the standard email registration which goes through AINative) will see empty data on all pages after login. They are authenticated but have no company data.

## Test Infrastructure Notes

### Auth Injection Strategy Used
The Next.js server-side middleware performs a 307 redirect to `/login` if no `token` cookie is present. Standard localStorage injection (via `addInitScript`) does not prevent this redirect because the cookie check happens at the server BEFORE the page is served.

**Solution implemented:**
```javascript
// 1. Add token as browser cookie BEFORE page.goto()
await page.context().addCookies([{
  name: 'token', value: JWT, domain: 'opencapstack.com',
  path: '/', httpOnly: false, secure: true, sameSite: 'Lax'
}]);

// 2. Set localStorage keys via addInitScript for client-side auth
await page.addInitScript(({ tok, usr, prof }) => {
  localStorage.setItem('token', tok);
  localStorage.setItem('user', JSON.stringify(usr));
  localStorage.setItem('ocs_profile', JSON.stringify(prof));
}, { tok, usr, prof });
```

This two-layer injection correctly bypasses both the server-side middleware and the client-side auth state.

### Key localStorage Keys (from Next.js bundle analysis)
```
token          — primary JWT (set on login, cleared on logout)
refreshToken   — refresh token
user           — JSON user object
ocs_profile    — JSON profile { companyId, role, plan, profileCompleted, onboardingCompleted }
```
